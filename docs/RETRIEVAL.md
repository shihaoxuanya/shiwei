# 检索与回答

拾微使用随包 jieba 词典进行本地搜索分词，移除疑问词和停用词，保留完整文件名与英文错误码。Unicode 和 trigram FTS 使用关键词而非中文整句。文件名/标题增加参数化子串召回，两字词也可命中；仅当 FTS 和元数据均未命中时，正文使用有上限的子串回退（最多扫描 50,000 个候选片段，每段最多 12,000 字符）。0.2.1 migration 6 自动重建本地派生检索投影，不要求重新导入资料。

原 Query + 2–3 条确定性 Rewrite 各走全文和可选 LanceDB 语义检索，每通道各取最多 20 条候选。按 chunkId 多路 RRF 融合、去重（k=60，按查询数归一化），仅对通过门槛的候选增加有限标题和时间相关加分，最终保留 12 条以内。模型/端点或 search_text 版本不一致时不混用旧向量。

`ContextBuilder` 负责内容去重、片段去重、6,000 token 预算与 Citation ID 分配。发送给模型的每个片段都包含真实引用 ID：文件使用 `[S1]`，笔记使用 `[N1]`；文件附页码/章节，笔记附创建与修改时间。Python 只接受本次上下文中确实存在的 Citation ID；流式输出也缓冲并过滤跨 token 的伪造 ID。资料回答完全没有有效引用时不把模型文本展示为可信资料结论。

`Assistant` 先处理明确问候、文件定位、资料库概览。文件匹配只产生 `sourceMatches` 元数据卡片，不伪装成正文引用。指定文件总结用该文件的有限片段；追问使用最近六条消息中最后一个回答的有效来源，多份或已删除来源要澄清。

普通问题允许无资料调用对话模型；个人经历/文件问题必须依靠资料，不自动改成通用回答。个人检索未命中时不再调用模型放宽关键词。非个人、非明确通用的模糊请求仍可最多一次只含问题文本的意图识别，但不使用返回的 keywords 覆盖原问题重新检索。指定来源的泛总结/已验证追问才能用 scoped_context，日期/主题问答不能借标题部分命中绕过 Gate。

文件与笔记进入同一 FTS5、向量和融合排序管线；`source_type` 只用于展示和行为边界，不要求用户切换搜索范围。笔记保存时仅替换受影响文档的 chunks、FTS 和 embedding，删除后旧 chunk 无法再被 hydrate，避免幽灵结果。

LanceDB 只保存 chunk ID、document ID、向量和 embedding 版本。SQLite/Canonical Document 是重建基础。更换对话模型不重建索引；更换 Embedding 模型后通过设置页重建，并在 `embedding_versions` 中切换 active 版本。

没有配置模型时，导入、资料浏览和 FTS5 仍可使用。对话页会展示本地全文搜索结果和出处，但不会假装生成 AI 总结。

## 0.2.1 检索契约

- `search_text` = 标题 + 两次换行 + 原始正文/片段；FTS Unicode 接收搜索分词文本，trigram 接收原始派生文本，向量接收同一 search_text。命中后重新 hydrate 原始正文，索引分词文本不能成为引用内容。
- Note/Document 与 Chunk 保存 `mentioned_dates` JSON ISO 日期集合，只提取有效明确日期，不把创建/修改/导入时间当作会议日期。Chunk 只包含标题和本片正文提到的日期，不传播整篇其他会议的日期。
- QueryPlan 将“开了个会/开会”归一为“会议”，“几号/哪天/什么时候”识别为时间意图；保留主体、否定条件、年份、完整日期和无年份月日。非法日期拒绝，不猜年份。Rewrite 不生成答案，不调用模型，不改变原文。
- Relevance Gate 始终对原始 QueryPlan 评分。候选必须有主题证据；明确技术名称/会议词缺失、日期矛盾、排除主题、时间问题缺少明确日期或缺失主题分面时拒绝。非时间问题要求至少 50% 主题覆盖；只有已有部分词面证据且 cosine >= 0.82 时容许覆盖降低至 25%。这是保守启发式，不是校准的概率分数。
- 语义分数使用明确的 cosine 距离转换；高向量分不能覆盖主体/日期硬约束。可选 embedding 或向量检索故障回退本地全文。没有可靠候选时不向回答模型发送无关资料。
- Context 去重键包含 documentId、明确日期、正文。同正文但不同来源/日期保留独立 Citation，不能隐藏多场会议的歧义。
- 旧版正文向量保留但暂停参与检索，设置中既有索引状态显示“需更新，当前使用本地全文检索”；既有重建操作或后续增量索引流程会按 version 1 更新。迁移不隐式上传全库重建向量。

## 开发评测与 Trace

运行 `services/ai-worker/.venv/Scripts/python.exe scripts/evaluate-retrieval.py` 评测合成库；加 `--query "我之前开了个会是在几号？" --semantic-fixture` 查看原 Query、Rewrite、每路 FTS/Vector Hits、Fusion、门槛拒绝原因及最终 Context/分数。实际已有 schema 6 库可以 `--db <path> --query <query>` 只读检查，工具拒绝迁移旧库。默认不输出正文/本地路径，仅显式 `--include-content` 可输出正文。`HybridRetriever(debug=True)` 仅开发调用；生产 Worker 不启用，聊天响应和 UI 不展示 debugTrace，服务日志不记录正文或查询。

当前合成评测未暴露“正确候选已召回但持续排后”的问题，因此不加入 Reranker。已知保守边界：没有明确事件日期、跨远距离片段才能关联日期、未覆盖的口语表达仍可能拒答；不同场次不确定时不能猜一场。本轮没有引入知识图谱、Agent Framework 或用户功能。
