# 网络取消与算式识别优化

本轮仅处理用户指定的两项，不修改连续追问、检索算法、数据库或界面。

- 旧取消只在同步请求前后、收到下一个 token 时检查。现在生产 HTTP 对话请求使用独立客户端与异步网络任务；主线程每 50ms 检查取消，取消任务并关闭连接。网络线程不接触 SQLite。有限队列提供背压，完成/取消均清理任务，不关闭共享 Provider。模型服务器是否停止远端计算或计费仍由厂商决定。
- 兼容 OpenAI-compatible 和 Anthropic 的普通/流式请求，包括意图识别及回答修复所用的普通请求。不改变非对话任务的网络机制。
- 算式路由支持全角数字/符号、中文数字和加减乘除、括号与口语结尾。只识别完整算式，不执行 eval，不替换用户原始问题。文件名、个人回忆、会议内容和日期继续留在原检索路径；额外排除斜杠日期。

验证：本地真实 HTTP socket 的等待响应头、等待响应体、SSE 中途停顿 × 两种协议共 6 项测试通过。断开连接、取消后重新请求、后台网络线程清理均有断言；取消上限断言为 1.5 秒，不以界面提前隐藏代替取消。算式与边界测试共 35 项通过。实际 JSONL Worker 集成的 5 个模糊召回、8 个拒答及资料/笔记/历史流程通过。

测试均使用合成数据和本地服务，没有读取真实资料库或使用生产 API Key。当前为源码验证，未重新打包 EXE、未执行安装包 UI 验收或发布。
