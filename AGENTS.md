# 拾微工程说明

Run the application, worker, and tests yourself. Do not give the user setup steps when the environment can be prepared directly.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## Durable product decisions

- Release hosting (2026-09-15): source repository `shihaoxuanya/shiwei` is to be public under MIT; `shihaoxuanya/shiwei-releases` hosts installers. Remove and decommission the Shiwei control plane, including its server data. Never publish credentials or personal data, including in Git history.

- `docs/PRODUCT.md` defines the current MVP; `docs/PRODUCT_VISION.md` is the long-term Product / Architecture North Star, not a feature backlog or implementation authorization. Optimize reliable personal recall over storage features. Preserve user-owned memory separately from rebuildable indexes and replaceable models. Future capabilities require explicit user tasks; do not use the vision to refactor stable modules, expand navigation, introduce large frameworks, or implement Agent/GraphRAG, sync, mobile, or cross-app services proactively. Report discovered technical debt without fixing it unless requested.
- Product name is `拾微`; use it consistently in application chrome, installers, exports, and user-facing copy.
- The production desktop architecture is Tauri 2 + React/TypeScript + a Python 3.11+ AI worker. Electron is legacy prototype code and must not be extended.
- Windows releases launch only the application window: link the Rust executable as a GUI application and start every Worker path with CREATE_NO_WINDOW while keeping piped JSONL stdio. Do not hide the bug using a launcher, disable Worker stdio with pythonw/--windowed, or close a user's terminal. Packaged smoke tests must verify the PE subsystem and absence of console window handles for both processes; an attachable headless console is not a visible window.
- The explicitly authorized Mac test distribution targets Apple Silicon (including M1 Pro), macOS 14+, using a native GitHub macos-14 runner and an Ad-hoc signed DMG. Keep Windows release behavior intact; no Intel support or new product features. Stage Mac sidecars separately, retain adjacent _internal and JSONL pipes, and never fall back to development Python/uv in a production build. Publish only installers/checksums/test notes as a non-latest mac-test pre-release in the public artifact repository; never register it for Windows stable rollout. Apple notarization is not included; do not disable Gatekeeper. Report native checks and tester first-install checks separately, and never claim a Mac package exists before its real build succeeds.
- Python is the only writer for SQLite, FTS5, canonical documents, jobs, and vector indexes. Rust owns desktop lifecycle, OS integration, and the worker process.
- The product is local-first with no account, Shiwei backend, telemetry, error uploads or automatic updater. Preserve local memory and user-selected model endpoints; online models can receive disclosed evidence/indexing text. GitHub downloads are explicit user actions only. This 2026-09-15 decision supersedes all previous telemetry/control-plane decisions.
- Privacy copy must distinguish local memory, user-selected model services, and the absence of Shiwei statistics. Online chat may send the question, necessary recent conversation history and selected evidence; online semantic indexing processes all derived title/body text chunks and queries, not only a few snippets when asking. Local endpoints are not necessarily internet services. Never equate "not uploaded to Shiwei" with "never leaves this computer".
- The core navigation is 首页、对话、资料、笔记、设置. Do not reintroduce the prototype's classification or discovery destinations.
- Preserve a quiet, restrained, modern Chinese interface, but prioritize the import-to-recall workflow over decorative dashboard features.
- Original source files are immutable truth; parsed documents and indexes are rebuildable derived data.
- The authorized “更改位置” action relocates the entire managed library (files, notes, conversations and derived indexes) into a new unique Shiwei subdirectory of the selected parent. Python copies under an exclusive library lock, verifies contents/SQLite and rewrites only managed paths in the copy, then atomically commits an external location pointer. Keep the original library as a retained snapshot; never overwrite destination content, delete originals, or switch before verification. Missing/corrupt saved locations must error, not silently create an empty library. Migration must block concurrent writes, repeated starts, updates and ordinary close until its final outcome; no model calls or automatic index rebuild.
- Model access goes through a replaceable ModelGateway. Changing the chat model never rebuilds the knowledge base; changing the embedding model may rebuild the vector index.
- Settings should prefer provider and model selectors with sensible presets over free-form fields; retain custom endpoints/model IDs. Chat and embedding providers can be configured independently, and providers without embeddings must still work for chat.
- Settings use AI 服务、数据与隐私、关于 sections. Saved configuration is not tested connectivity; test chat and retrieval separately with synthetic text. Advanced controls may collapse, but outbound-data/cost disclosures stay visible. Only explicit confirmation after an effective embedding-service change starts bulk reprocessing; chat-only changes do not rebuild indexes. Do not expose unimplemented export/backup controls.
- PDF import must work without downloading layout models at runtime: extract text locally, OCR scanned pages locally, preserve page citations, and expose actionable errors with retry.
- The authorized large-file/web capture slice raises local files to 1 GiB inclusive and PDFs to 3000 pages inclusive, with disk preflight, page/OCR progress and terminal-state long-task waits. Public HTTP(S) web pages are captured once as immutable local snapshots, indexed by the existing canonical pipeline, safely read offline and cited by paragraph. Deduplicate normalized submitted URL + extracted body hash; changed body creates a new source, and different URLs retain separate identities. Reindex never refetches. Reject authenticated/private/special/DNS-rebound destinations and file direct links; no browser cookies, script execution, remote media or recursive crawling. Web fetch is independently capped at 20 MiB decompressed, 60 seconds and 5 redirects. Never upload URLs/body to telemetry or logs. This task does not authorize publishing GitHub or server updates.
- Conversation is knowledge-first and also supports everyday/general chat. Personal facts require verified local evidence; missing records must never fall back to fabricated personal answers. File matches are metadata cards, separate from body citations. Chinese recall must work with semantic search disabled and without re-importing existing sources.
- Conversation UX prioritizes continuous reading and follow-up: keep the multiline composer reachable, preserve active conversations and per-conversation drafts across navigation, retain background replies in their originating conversation, and let users inspect sources without blocking the composer. Preserve the established paper/indigo visual language.
- Notes are a deliberately minimal first-party memory input: title is optional, body auto-saves, notes share the canonical document/FTS/vector retrieval pipeline, and the product must not grow Obsidian/Notion-style folders, tags, backlinks, block editing, templates, graphs, canvases, or plugins in this MVP.
- The home page is only for adding and continuing information processing, never a second conversation composer. Empty libraries show a concise welcome and clear file/folder import plus “记一下” actions; populated libraries use a compact welcome, real processing/failure feedback and at most five real recent files/notes. Worker details belong in Settings diagnostics, with only a quiet local-service indicator in normal navigation and actionable errors when unavailable.
- v0.2.1 (v0.21) is retrieval reliability only: no new user features. All notes/documents derive title + body `search_text` for FTS and embeddings without rewriting originals. Use deterministic query normalization, original + 2–4 rewrites, deduplicated multi-query fusion, explicit-date metadata, and an original-query relevance gate before sending context to a model. Never relax absent entities/dates through a planner or weak filename match. Developer traces are opt-in and absent from production UI. Evaluate recall, rank, citation identity and abstention before considering a reranker; no knowledge graph or large agent framework.
- Answer fidelity is a strict boundary: never mutate stored notes to fix presentation. Normalize only unambiguous prose numeric ranges in derived context/answers, preserve code/URLs, and disable single-tilde Markdown strikethrough. Separate source facts from explicitly conditional calculations/inferences; never attribute a derived project duration to meeting records. Group same-source paragraph/list citations conservatively without dropping distinct source mappings. Note chips show title only; explicit mentioned dates and creation/update timestamps belong in the source drawer with distinct labels. Topic-related candidates are not automatically answer evidence; meeting questions require meeting evidence, and absent personal records must still abstain. Keep evidence-selection diagnostics developer-only; add no new product features for this work.

Build the production UI in `apps/desktop/src/`, the Rust shell in `apps/desktop/src-tauri/`, and the Python worker in `services/ai-worker/`. Legacy prototype files remain only as migration reference until the Tauri vertical slices replace them.
